PHP 8.1 セキュリティ修正・ローカルビルドキット
作成日：2026-10-22

公開済みRPMをEC2へ導入する場合はREADME.mdの「AWS EC2の既存PHP 8.1を更新する」から進めます。
自分で再ビルドする場合の詳しい手順はREADME.html / README-ja.mdにあります。

【これは何か】
手元の PC で修正済み PHP 8.1 の RPM を作り、GitHub などを通じて
Amazon Linux 2 の本番 EC2 に渡すための手順とスクリプトです。
GitHubのソースZIPにはコンパイル済みRPMは入りません。完成バイナリは次のReleaseにあります。
https://github.com/YashubuStudio/PHP8.1.34-AmazonLinux/releases/tag/php81-8.1.34-cve20261021.1

【計算する場所】
重いコンパイル処理は、すべて手元の PC で行います。
Amazon Linux 2 のコンテナも、その PC 内で動かします。
ビルド用EC2やGitHub Actionsではコンパイルしません。
GitHub Actionsは、ローカルで検証した完成物の照合とRelease公開だけに使用します。

【再ビルドに必要なもの】
・手元の x86_64 Ubuntu PC、または Windows＋WSL 2 Ubuntu
・手元で動く Docker。一般ユーザーで docker info が成功すること
・目安：ビルド用 CPU 2 コア分、メモリ 4 GiB＋OS 用の余裕、空き 20 GiB 程度
・インターネット接続
・自分で管理する GitHub リポジトリ（非公開でも可。SCP 直接転送も可）
・本番 EC2 に接続するいつもの SSH 接続先・鍵・sudo 権限

【自分で再ビルドする場合の順番】
1. 手元で Docker を準備し、この ZIP を ~/work に展開する。
2. 手元でキットのフォルダに移動し、次を実行する。
     sha256sum --check --strict KIT-SHA256SUMS
     BUILD_JOBS=2 bash build-local.sh
   sudo bash build-local.sh では実行しない。
3. 成功後にvalidate-local.shで完成RPMを試験し、検証記録付きバンドルを作る（README.md参照）。
   検証済みのtar.gzとtar.gz.sha256をGitHub Releasesに置く。
4. 本番へ完成ファイルを取得・検証し、README.md手順3の外部修正版コピーを作る。
   公開済み旧Releaseの同梱スクリプトではcpioの一時展開エラーが報告されています。
   php81-install-stage-fix.sh check を実行する。
5. PRECHECK OK を確認し、作業時間に apply を実行する。
6. RPM の版、PHP-FPM の稼働、既存サイトを確認する。

本番への正確なコマンド、GitHub の使い方、Windows の準備、エラー対応、
切り戻しは README.html に記載しています。手順の実行場所を確認してください。

【本番の対象】
Amazon Linux 2 / x86_64、AWS 版 PHP 8.1.34-1.amzn2 の指定 8 パッケージ。
更新後も PHP 8.1 を維持します。php -v の 8.1.34 表示は変わりません。
確認には RPM の Release（1.amzn2.cve20261021.1）を使います。

【本番停止が起きるタイミング】
apply と rollback のときだけ、PHP-FPM を一時停止します。
ビルド中に本番サイトを止める必要はありません。
